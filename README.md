# 교회·모임 금전출납부 (모바일 웹앱 · 여러 명 공유)

수입·지출을 적고, 영수증 사진을 붙이고, 달마다·해마다 결산을 뽑아 **A4로 인쇄하거나 PDF로 저장**하는 앱입니다.
`index.html` 파일 하나로 동작하며(외부 라이브러리 없음), 입력한 내용은 **구글 시트에 바로 저장되어 여러 기기·여러 사람이 같은 장부를 함께 씁니다.**

- 만든 날: 2026-11-21
- 참고: `documents/교회-금전출납부-샘플.xlsx` 의 계정과목·누계 방식을 그대로 따랐습니다.

## 1. 여는 방법

1. 주소를 엽니다: **https://hanseong1007.github.io/church-ledger/**
2. **아이디·비밀번호로 로그인**합니다. 계정은 관리자에게 받으세요. (처음 관리자 계정은 `admin` / `admin1234` — 로그인 후 꼭 바꿔 주세요.)
   로그인 전에는 장부 내용·금액·영수증이 하나도 보이지 않습니다.
3. 브라우저 메뉴 → **홈 화면에 추가** 를 하면 앱처럼 전체 화면으로 열립니다.
   - 삼성 인터넷: 메뉴(≡) → 홈 화면에 추가
   - 크롬: ⋮ → 홈 화면에 추가
4. 한 번 로그인한 기기는 30일 동안 유지되고, 앱을 다시 열면 자동으로 들어갑니다.
   다른 사람에게 빌려준 기기라면 **설정 → 로그아웃**을 눌러 주세요.
5. 주소만 같으면 **누가 어느 기기에서 열어도 같은 장부**가 보입니다.
   기록은 이 기기(localStorage)에 먼저 저장되고, 동시에 구글 시트로 전송됩니다.

## 2. 공유 데이터와 로그인 보안 (구글 시트 + Apps Script)

- 데이터 그릇: 「교회 금전출납부 (공유 데이터)」 스프레드시트 (탭: `거래내역`, `설정`, `계정`, `세션`).
- 앱 화면 위 **☁️ 상태 줄**에 연결 상태가 보입니다. `☁️ 동기화 완료 (방금)` 이면 공유 중입니다.
- **🔄 새로고침** 을 누르면 다른 사람이 방금 넣은 내용을 즉시 받아옵니다.
  누르지 않아도 **20초마다**, 그리고 앱으로 돌아올 때마다 자동으로 받아옵니다.
- 입력·수정·삭제·설정 변경은 **곧바로 구글 시트에 저장**됩니다.
- 인터넷이 끊기면 `⚠️ 이 기기에 저장됨` 으로 표시되고, 연결되면 **자동으로 올라갑니다**.
- 전에 이 브라우저에만 있던 기록이 있으면, 처음 연결될 때 **자동으로 시트에 올라갑니다**(같은 id 는 최신 것만 남김).
- 서버 프로그램은 `apps-script/Code.gs` (구글 Apps Script 웹앱)입니다. 구글 시트 → `확장 프로그램` → `Apps Script` 에서 관리합니다.

> 🔒 **주소를 알아도 로그인 없이는 아무것도 못 봅니다.** 장부를 읽고 쓰는 모든 요청은 서버(Apps Script)에서
> 로그인 토큰을 확인하고, 없으면 `unauthorized` 로 거절합니다. 시트 주소를 아는 사람이라도 앱을 거치지 않고는
> 데이터를 가져갈 수 없고, 앱 쪽에서도 로그인 전에는 장부 화면 자체가 열리지 않습니다.
> - 비밀번호는 **SHA-256 + 계정별 salt 해시**로만 `계정` 시트에 저장합니다(원문 미보관).
> - 로그인 세션은 `세션` 시트에 30일 토큰으로 보관하고, 사용하면 자동 연장됩니다.
> - 비밀번호를 바꾸면 그 계정의 기존 기기 세션은 모두 해제됩니다.
> - 같은 아이디로 10분에 8번 틀리면 잠시 로그인이 막힙니다.

## 3. 계정과 권한

| 구분 | 할 수 있는 일 |
|---|---|
| 관리자(`admin`) | 장부 전체 + **사용자 관리**(계정 추가·비밀번호 초기화·사용중지·삭제) + 내 비밀번호 변경 |
| 일반 사용자 | 장부 전체(보기·입력·수정·인쇄·백업) + 내 비밀번호 변경 |

- 처음 기본 계정은 **`admin` / `admin1234`**(이름: 관리자)입니다. 이제 로그인 화면에는 비밀번호 안내를 띄우지 않으므로, 새로 쓰는 사람에게는 관리자가 아이디·비밀번호를 알려 주세요.
- **설정 → 사용자 관리**에서 아이디·이름·권한·비밀번호를 넣어 계정을 추가합니다. 이름은 장부의 작성자로 자동 기록됩니다.
- **샘플 데이터 채우기**와 **전체 초기화**(공유 시트까지 지우는 기능)는 **관리자만** 할 수 있습니다.
- **비번 초기화**는 그 사람의 새 비밀번호를 관리자가 정해 주는 방식입니다. 잊어버렸을 때 사용하세요.
- **사용중지**는 계정을 지우지 않고 로그인만 막습니다. 나중에 **다시 사용**으로 되돌릴 수 있습니다.
- 관리자는 최소 한 명이 남아야 하며, 지금 로그인한 계정은 스스로 삭제할 수 없습니다.
- 관리자 비밀번호를 잊어버렸을 때: 구글 시트 → `확장 프로그램` → `Apps Script` → 함수 목록에서 `resetAdminPassword` 실행 → `admin`/`admin1234`로 되돌립니다.

## 5. 탭 설명

### ① 장부
- 상단에 **현재 잔액**(기초 이월금 + 수입 − 지출)과 수입·지출 누계가 보입니다.
- **수입 기록 / 지출 기록** → 금액, 날짜, 항목, 적요, 결제·수단, **영수증 사진**을 넣고 저장.
- 항목에서 **＋ 직접 입력…** 을 고르면 새 계정과목이 만들어져 설정에 저장됩니다.
- 목록은 달마다 묶여 최신순으로 나오고, 줄마다 **그 시점의 잔액**이 함께 표시됩니다.
- 줄을 누르면 **수정/삭제**, 영수증 썸네일을 누르면 **크게 보기·사진 저장**.
- 위쪽 **전체 기간**에서 달을 고르거나, **항목·적요 검색**으로 찾을 수 있습니다.
- **장부 인쇄**(목록형)와 **출납부 표 인쇄**(표 양식) 두 가지로 A4 출력·PDF 저장을 할 수 있습니다.
  - **출납부 표**는 `번호 · 날짜 · 항목 · 내용 · 수입 · 지출 · 누계` 7칸 표로, 첫 줄에 **이월금**을 넣고
    그 아래로 날짜순(오래된 순)으로 이어지며 맨 오른쪽 `누계`가 차례로 계산됩니다. 맨 아래에는 **합계 행**(수입 합계·지출 합계·기말 잔액)이 붙습니다.
  - 위에서 고른 기간을 그대로 따릅니다. **한 달을 골랐으면 `전월이월금`**(그 전 달 말 잔액), **전체 기간이면 `기초이월금`**(설정의 기초 이월금)이 1번 줄입니다.
  - 작성자·확인자 서명란과 계산 기준 설명도 함께 인쇄되고, 여러 장이면 머리글(번호·날짜…)이 페이지마다 반복됩니다.

## 7. 영수증 사진

- **촬영**(카메라) 또는 **갤러리**에서 고릅니다.
- 자동으로 긴 변 960px 안축에서 JPEG로 줄입니다. 시트 한 칸(50,000자)에 들어가도록 **42,000자 이하**가 될 때까지 크기·압축률을 단계적으로 조정합니다(보통 25~40KB). 원본은 보관하지 않습니다.
- 폰 사진을 읽는 순서: ① 브라우저의 `createImageBitmap`(빠르고 메모리 절약, 사진 회전 자동 처리) → ② `URL.createObjectURL` → ③ `FileReader`. 한 단계가 안 되면 다음 단계로 넘어가므로 삼성 인터넷·안드로이드 WebView에서도 대부분 열립니다.
- `type`(파일 종류)이 비어서 오는 안드로이드 파일 선택기도 **확장자(.jpg .png .webp .gif .bmp)** 로 판단해 받아들입니다.
- 아이폰 **HEIC**처럼 브라우저가 열지 못하는 형식이면 "사진을 읽지 못했습니다" 대신 **변환 안내**(사진 앱에서 JPEG로 복사·저장)가 나옵니다.
- 썸네일을 누르면 크게 보고 **사진 저장**으로 내려받을 수 있습니다.
- 영수증은 구글 시트의 `receiptData` 칸에 함께 저장되어 다른 기기에서도 보입니다.

## 8. 데이터 보관 주의

- 기록의 본 저장소는 **구글 시트**이고, 이 기기 브라우저(localStorage)는 입력을 바로 잡아 두는 **임시 저장소**(약 5MB) 역할을 합니다.
- 브라우저 데이터를 지워도 구글 시트 내용은 그대로 남습니다. 다음에 열면 다시 받아옵니다.
- 영수증은 100장에 약 3MB 정도이므로, 설정의 사용량이 **65%를 넘으면 백업(JSON) 후 오래된 사진을 정리**하는 것이 좋습니다.
- 같은 기록을 동시에 고치면 **나중에 저장된 것**이 남습니다. 누가 무엇을 고쳤는지는 시트의 `author`·`updatedAt` 열로 확인할 수 있습니다.
- 내용을 통째로 되돌리고 싶을 때는 연간 탭의 **백업(JSON) 저장**을 먼저 해 두세요.

## 12. 덕신교회 통합 포털 (`/portal/`) — 2026-11-26 · **2026-11-28 통합 로그인 일원화(v3)**

**통합 아이디·비밀번호 하나**로 포털에 로그인하면, 금전출납부·재정보고·중보기도문이 **각자의 로그인 화면 없이** 바로 열립니다.
2026-11-28부터 **앱마다 따로 두던 아이디·비밀번호(앱 비밀번호 설정)는 없앴습니다.** 포털 안에도 그런 입력칸이 없습니다.

### 계정·권한은 어디에 있나

| 무엇 | 어디 |
|---|---|
| 아이디·비밀번호(해시)·이름·사용 앱·사용 중지 | 기존 교회 암호화 시트의 `portal-acct` 슬롯(중보기도문 동기화 Apps Script)에 JSON 한 덩어리 |
| 비밀번호 | PBKDF2-SHA256(210,000회, 계정마다 다른 salt) 해시만. **평문은 시트에 남기지 않습니다** |
| 통합 비밀번호 봉인 | 이 기기에서만 풀리는 `dkp.pass.v1` (IndexedDB의 꺼낼 수 없는 CryptoKey `dkp-dev`로 AES-GCM). 로그아웃하면 함께 지웁니다 |

| 중보기도문 계정 | 중보기도문 동기화 Apps Script의 `acct-…` 슬롯 — 역시 **같은 통합 아이디·비밀번호**. 포털에서 비밀번호를 바꾸면 서버 계정과 계정 봉투(작업 열쇠)까지 함께 바꿉니다 |

### 1회 로그인으로 앱이 열리는 방식

1. 포털 로그인 → 금전출납부 서버에서 토큰을 받아 `church-ledger-auth-v1`에 넣습니다 → 금전출납부는 그대로 열립니다.
2. 포털이 이 기기에 **통합 비밀번호 봉인(`dkp.pass.v1`)** 을 남깁니다. 재정보고·중보기도문은 그것만 풀어
   `window.__dkpEnter` 로 스스로 들어갑니다(입력칸 없음).
3. 재정보고 금고가 예전 비밀번호(`admin1234` 등)로 잠겨 있으면 **한 번만 조용히 열고 곧바로 통합 비밀번호로 다시 잠급니다.**

4. 권한이 없는 앱은 주소로 직접 들어가도 `이 도구를 쓸 권한이 없습니다` 화면으로 막습니다.

   포털에서 로그인하면 그 앱으로 바로 돌아옵니다(두 번 넘게 되돌아오면 자동 이동을 멈추는 무한 되돌이 방지 장치가 있습니다).

## 13. 보안 강화 (2026-11-27) — 1~4번 적용

같은 교회 앱(금전출납부·부서업무·중보기도문·통합포털)에 다음 네 가지를 넣었습니다.

### 1) 서버 로그인 확인 + 서명 토큰 (12시간)
- 로그인은 **Apps Script 서버가 직접** 확인합니다. 성공하면 서버 속성(`PropertiesService`)의 비밀키로 서명한
  **HMAC-SHA256 토큰(12시간 만료)** 을 발급합니다. 토큰에는 계정·권한·만료·비밀번호 판본이 들어 있어
  **위조·만료·비밀번호 변경 뒤의 토큰은 거부**됩니다.
- 자료를 다루는 모든 API(조회·저장·승인·계정관리)는 토큰이 없으면 `{"ok":false,"error":"unauthorized"}` 만 돌려줍니다.
- 계정 목록·비밀번호 해시·salt 는 로그인 전에 내려가지 않습니다(부서업무는 `setup_state`, `signup_check` 만 열려 있음).
- 부서업무·중보기도문은 비밀번호 원문을 서버로 보내지 않고 `SHA-256('deoksin-edu-login:'+아이디+':'+비밀번호)`
  같은 파생값만 보냅니다(서버는 salt+파생값의 해시만 보관).
- 부서업무·중보기도문의 기존 계정은 **이번 업데이트 뒤 첫 로그인 때 한 번** 서버에 비밀번호가 등록되고,
  그다음부터는 서버가 직접 확인합니다(기존 비밀번호 그대로 사용).

### 2) 자료 암호화
- **금전출납부**: 시트에 저장하는 항목·적요·결제·금액·작성자·영수증을 **AES-256-GCM**(`enc1:`)으로 암호화합니다.
  키는 스크립트 속성에만 있고 HTML/JS 에는 없습니다. 영수증 암호문은 한 칸(50,000자)을 넘을 수 있어 뒤 두 칸에 나눠 저장합니다.
  기존 평문 기록은 관리자 `encrypt_all` 로 한 번에 암호화했고(백업 후, 내용 동일 검증), 옛 평문 행도 그대로 읽힙니다.
- 부서업무·중보기도문은 이미 브라우저에서 AES-256-GCM 으로 암호화해 올리고 있어 그대로 유지했습니다.
  서버에는 암호문만 저장됩니다.

### 3) 무단 접속 차단 · 자동 잠금
- **5회 연속 실패 → 15분 잠금** (서버가 셈, 없는 아이디도 동일).
- **30분 미사용 시 자동 로그아웃** (금전출납부·부서업무·포털).
- 주소를 직접 입력해 들어와도 토큰이 없으면 자료가 하나도 내려가지 않습니다.

### 4) 감사 로그 · 자동 백업 · 초기 비밀번호 강제 변경
- `보안로그` 탭: 로그인 성공/실패/잠금, 수정, 계정 추가·삭제, 비밀번호 변경 (시각·아이디·작업·결과·기기·비고).
- `백업` 탭: 하루 1회 스냅샷(7일 보관). 금전출납부는 거래·설정·계정, 부서업무는 계정·보안계정.
- `admin1234`·`deoksin2026` 같은 기본 비밀번호로 로그인하면 **비밀번호를 바꾸기 전까지 다른 기능이 막힙니다.**
  관리자가 정해 준 비밀번호로 만든 계정도 첫 로그인 때 바꿔야 합니다.

### 지금 상태에서 꼭 알아 둘 점
- **금전출납부 관리자(`admin`)가 아직 `admin1234`** 입니다. 다음에 열면 비밀번호 변경 화면이 먼저 나옵니다.

## 14. 보안 강화 뒤 생긴 막힘 복구 (2026-11-27 밤)

현장에서 보고된 두 가지 — ① 포털에서 중보기도문이 열리지 않음, ② 금전출납부 비밀번호 변경 화면에서 다음으로
넘어가지 않음 — 의 원인을 찾아 고쳤습니다.

### ② 금전출납부: 변경 화면이 아무 말 없이 멈춘 것처럼 보이던 문제
- `.login-err` 칸은 `show` 클래스를 붙여야 보이는데, 변경 화면 코드는 글자만 넣고 `show` 를 붙이지 않아
  **"새 비밀번호는 6자 이상", "서로 다릅니다", "지금 쓰는 비밀번호가 맞지 않습니다"** 같은 안내가 화면에
  하나도 나오지 않았습니다. 이제 `pcError()` 로 항상 보이게 했고, 서버가 준 오류 문구도 한글로 풀어 보여 줍니다.
- 비밀번호를 바꾸면 **포털이 이 기기에 저장해 둔 통합 비밀번호 봉인(`dkp.pass.v1`)도 새 값으로 바꿔** 둡니다.
  (2026-11-28 이전의 앱별 봉인 `dkp.seal.v1`은 더 이상 쓰지 않고 지웁니다.)
- **변경 직후 로그인 화면으로 튕기던 경합**도 고쳤습니다. 변경 전에 나가 있던 자동 동기화 요청이 늦게
  돌아와 옛 토큰으로 `unauthorized` 를 받으면 앱이 로그아웃시켰기 때문입니다. 이제 토큰 세대(`AUTH_EPOCH`)가
  바뀐 뒤 도착한 응답은 무시하고, 비밀번호 변경 화면에서는 자동 동기화를 멈춥니다.

### ① 중보기도문: 포털에서 열리지 않던 문제 (원인 세 가지)
1. **계정 봉투를 먼저 읽던 순서**: 서버가 토큰 없는 `acct-…` 슬롯 읽기를 막은 뒤로는, 로그인 전에 계정 봉투를
   읽으려다 실패해 **"없는 아이디입니다"** 로 막혔습니다. 이제 서버 비밀번호 확인(`auth_state` → `auth_login`)을
   먼저 해서 토큰을 받고, 그다음에 봉투를 읽습니다.
2. **변경 창이 잠금 화면 뒤에 깔리던 문제**: `.mask` 의 `z-index:70` 이 `#lock` 의 `80` 보다 낮아,
   비밀번호 변경 창이 떠도 눌리지 않았습니다(화면에는 잠금 화면만 보임). `z-index:90` 으로 올렸습니다.
3. **바꾼 비밀번호로 열쇠가 안 풀리던 문제**: `auth_pw` 요청에 `slot` 이 빠져 서버가 `bad_slot` 으로 거절했고,
   바꾼 뒤 계정 봉투를 새 비밀번호로 다시 감싸지도 않았습니다. 이제 `slot` 을 보내고, 변경 성공 뒤 봉투를 새
   비밀번호로 다시 감싸 저장한 다음 바로 기도문 화면으로 들어갑니다. 포털 봉인도 함께 갱신합니다.

### 아직 남은 점
- 중보기도문 **관리자가 다른 사람 계정의 비밀번호를 바꾸는 기능**은 이 기기의 봉투만 바뀌고 서버에 등록된
  비밀번호는 그대로입니다(서버에 그런 요청이 없음). 지금 중보기도문 계정은 `admin` 하나뿐이라 실제 영향은 없지만,
  계정을 늘리기 전에 서버에 관리자용 비밀번호 변경 요청을 추가해야 합니다.

## 16. 2026-11-28 인쇄·동기화 수정 (v8 · 서버 v9)

사용자가 보낸 사진 4장으로 확인한 세 가지 문제를 고치고, 화면을 처음부터 다시 짚어 가며 손봤습니다.

### (1) `[출납부 표 인쇄]` 를 눌러도 카드형 장부가 인쇄되던 문제 — 고침

- **원인**: 인쇄할 때 화면에 `print-this` 클래스를 붙였다가 `afterprint` 가 오면 떼는 방식이었습니다.
  안드로이드 크롬은 인쇄 창이 끝나기 전에 `afterprint` 를 먼저 보내서, 인쇄 미리보기가 만들어지는 사이에 클래스가 떨어져 **지금 보고 있던 장부 화면**이 인쇄되었습니다.
  (그래서 `[장부 인쇄]` 는 정상, `[출납부 표 인쇄]` 만 장부로 나왔습니다.)
- **고침**: 출납부 표는 화면 클래스를 건드리지 않고 **인쇄 전용 문서를 새 창에 만들어 그 창에서 인쇄**합니다(통계·항목 인쇄와 같은 방식, 이 기기에서 이미 정상 동작하던 방법).
  - 표 양식: `번호 · 날짜 · 구분 · 항목(계정과목) · 내용(적요) · 수입 · 지출 · 누계`, 1번 줄 이월금(기초/전월), 마지막 줄 합계(수입·지출·기말 잔액), 작성자·확인자 서명란, 단위 원
  - 기간은 장부 탭에서 고른 기간(전체 또는 그 달)을 그대로 따릅니다.
  - A4 세로 · 4장(96건)으로 인쇄되고, 페이지마다 표 머리글이 반복되며 줄이 페이지 경계에서 잘리지 않습니다.
- 화면 인쇄용(`장부`·`월간`·`연간`)에도 안전장치를 넣었습니다: 인쇄 버튼을 누른 뒤 1.5초 안에 오는 `afterprint` 는 무시합니다.

### (2) 통계·항목별 조회 인쇄에서 건별 금액이 빠지던 문제 — 고침

- **통계 → 세부 내역까지 인쇄**: 이제 건마다 `날짜 · 구분 · 세부 내역 · 금액` 을 함께 적고, 항목마다 `○○ 계 · 건수 · 비중 · 금액` 소계 줄을 넣었습니다. 표가 길어 A4 **가로**로 인쇄됩니다.
- **항목별 조회 → 이 항목 인쇄**: 2단(수입/지출) 표 대신 `날짜 · 구분 · 세부 내역 · 금액` 한 표로 바꾸고 `수입 계 / 지출 계 / 수지` 를 표 끝에 넣었습니다. 결제·수단은 기록이 있을 때만 열로 나옵니다.
- 화면의 항목별 조회도 같은 모양(날짜·구분·세부 내역·금액 + 합계)으로 바꿔, 화면과 인쇄본이 같습니다.
- 합계 줄은 표 본문(`tbody`)에 넣어 **마지막 장에만** 나옵니다(머리글 반복은 유지).

### (3) `⚠️ Failed to fetch · 이 기기에 저장됨` — 원인과 고침

- **원인(측정으로 확인)**: 서버(Apps Script)의 응답이 너무 느렸습니다. `sync_all` 한 번에 **14~31초**가 걸렸고,
  앱은 화면을 열 때 `me` 와 `sync_all` 을 동시에 보내 두 요청이 서버 잠금(LockService)에서 줄을 서 **40~70초**까지 늘어졌습니다.
  그 사이 휴대폰 네트워크가 끊기거나 45초 제한에 걸리면 브라우저가 `Failed to fetch` 를 냅니다(데이터는 이 기기에 저장된 상태).
- **서버 쪽 원인**: 시트 값을 AES-256-GCM 으로 풀 때마다 `PropertiesService` 에서 암호 키를 **한 칸마다** 다시 읽고 있었습니다.
  96건 × 5칸 = 480번. (키 읽기 + 키 확장을 매번 반복)
- **고침(서버 v9, 같은 `/exec` 주소 유지)**: 키를 실행당 한 번만 읽도록 메모리에 둡니다.
  - `dataKey_()` · `secKey_()` 가 `DATA_KEY_CACHE_` · `SEC_KEY_CACHE_` 를 먼저 봅니다.
  - 측정: `sync_all` **14~31초 → 2.9~5.5초** (하루 한 번 도는 자동 백업 때만 ~15초)
  - 장부 96건·수입 15,527,664원·지출 13,473,186원·잔액 2,054,478원이 그대로임을 배포 뒤 curl 로 확인했습니다.
- **앱 쪽 고침**:
  - 화면을 열 때 `me` 를 따로 묻지 않고, 이 기기에 있던 장부를 **바로** 보여 준 뒤 동기화 응답으로 세션을 확인합니다(요청이 겹치지 않음).
  - 인터넷이 잠깐 끊기거나 응답이 늦으면 빨간 경고를 띄우기 전에 **2.5초·5초 뒤 스스로 두 번 더** 시도합니다.
  - 경고 문구를 우리말로: `Failed to fetch` → "인터넷 연결이 잠깐 끊겼습니다", 시간 초과 → "서버 응답이 늦어 시간이 초과되었습니다".
  - 동기화 배너의 🔄 새로고침은 1분 대기(`retryAt`)를 지우고 바로 다시 시도합니다.
  - 설정 → 공유 데이터에 **마지막 동기화에 걸린 시간**(예: "문제 없음 (7.0초)")을 함께 보여 줍니다.

### (4) 그 밖에 스스로 판단해 더한 것

- **월간 탭에 `[출납부 표 인쇄]` 추가**: 그 달 표를 이월금부터 바로 인쇄합니다(장부 탭의 기간 선택과 무관).
- **보고서 작성자**: 설정에 작성자를 비워 두어도 `작성자: —` 대신 **지금 로그인한 사람 이름**이 들어갑니다.
- 장부 탭의 안내문을 실제 동작에 맞게 고쳤습니다(장부 인쇄 = 화면 전체 카드형 / 출납부 표 인쇄 = 고른 기간 표).
